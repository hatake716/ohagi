# ohagi

niri(Wayland 向けスクロール型タイリングコンポジタ)にインスパイアされた Android ホームランチャーです。ホーム画面を「横に無限に拡がるカラムの列」として扱い、フォーカス中のカラムが常に中央にスナップされる操作感を Android 上で再現します。

- リポジトリ: https://github.com/hatake716/ohagi.git
- applicationId: `io.github.hatake716.ohagi`
- minSdk 26 (Android 8.0) / targetSdk 36 / versionName 0.1.0

## コンセプト

niri のワークスペースは「横一列に並ぶカラム」をスクロールして渡り歩くモデルです。ohagi はこれをホームランチャーとして解釈し、アプリを「カラム上のタイル(アプリカード)」として配置します。グリッドにアイコンを敷き詰める従来型のホーム画面とは異なり、カラムを足せば足すだけワークスペースが横に伸びていきます。

## 主な機能

- **スクロール型ワークスペース**: 横スクロールで無限に拡がるカラム列(niri の「無限に伸びる水平リボン」)。指に 1:1 で追従するスクロールと、フォーカス中カラムを中央へ吸い付けるスプリングスナップを備え、隣のカラムが端から覗きます。カラム幅は niri と同じ「1/3 → 1/2 → 2/3 → フル」の 4 プリセットを循環切替できます。
- **タイル領域への実ウィンドウ起動(フリーフォームモード)**: フリーフォームウィンドウが有効な端末では、タイルをタップするとそのタイルの矩形に**操作可能な実アプリウィンドウ**が開きます(リアルタイム描画・操作はこの実ウィンドウ側で行われます)。ドロワーやドックから開いたアプリは、**リボンの右端(既存ウィンドウの右)** に新しいカラムとして追加され、リボンがそこまでスクロールしてからウィンドウが立ち上がります(niri の「新しいウィンドウは右に」)。既にワークスペースにあるアプリは、そのカラムへフォーカスを移して開き直します。
- **macOS ライクなタイル**: タイルは大きめの角丸で、フォーカス中は小豆色の縁取りが太く光ります。非フォーカスのタイルは控えめな白縁で、スクロールに追従して滑らかに縮小・整列します。
- **カラムの 2 分割**: 各カラムはタイルを 1〜2 個持てます。2 個のときは縦画面で上下、横画面で左右に分割表示されます。フリーフォームモードの「分割起動」は 2 つのタイル矩形にそのまま 2 つのウィンドウを並べます。
- **分割画面での同時起動(フォールバック)**: フリーフォーム非対応端末では、2 タイルのカラムから 2 アプリを Android の分割画面で同時起動します(`FLAG_ACTIVITY_LAUNCH_ADJACENT` を使用)。一部メーカー ROM ではこのフラグが機能せず、分割起動できない場合があります。
- **ドック**: 4 スロット + 中央のランチャーボタン。各スロットにはアプリ単体またはフォルダを置けます。
- **ドック内フォルダ**: 空スロットやアプリ入りスロットをフォルダに変換し、複数アプリをまとめて管理できます(名前変更・追加・削除に対応)。
- **壁紙変更**: ホームメニューからシステムの壁紙ピッカーを呼び出せます。
- **ウィジェット非対応(意図的)**: タイル 1 枚 = アプリ 1 つというモデルをシンプルに保つため、ウィジェットはサポートしません。

## 操作方法

| 操作 | 動作 |
|---|---|
| タイルをタップ | アプリを起動(非フォーカスカラムのタイルは、タップでそのカラムへフォーカス移動) |
| タイルを長押し | タイルメニュー(起動 / 分割起動 / タイル追加による分割 / 上下・左右入替 / 幅切替 / カラム左右移動 / アプリ情報 / 削除) |
| 上スワイプ または 中央ボタン | アプリ一覧(ドロワー)を開く |
| 中央ボタンを長押し | ホームメニュー(アプリ追加 / 壁紙変更 / デフォルトホーム設定 / このアプリについて) |
| ドックスロットをタップ | アプリ起動 / フォルダを開く / (空なら)アプリ割り当て |
| ドックスロットを長押し | スロットメニュー(アプリ割り当て / フォルダ作成・変換 / 名前変更 / 削除 など) |

補足:

- タイルメニューの内容はカラムの状態に応じて変わります。タイルが 1 個のカラムでは「上(横画面では左)に追加」「下(横画面では右)に追加」で分割を作り、2 個のカラムでは「分割起動」「入替」が現れます。
- ホーム画面ではバックキーは無効です(ランチャーの標準挙動)。HOME 再押下でオーバーレイを閉じ、先頭カラムへ戻ります。

## アーキテクチャ概要

単一モジュール構成で、Jetpack Compose + DataStore(JSON シリアライズ)+ 手動 DI(`Graph`)というシンプルな作りです。レイアウトは `layout.json` として DataStore に永続化され、アンインストールされたアプリへの参照は自動的に掃除されます。

| ファイル | 役割 |
|---|---|
| `MainActivity.kt` / `OhagiApp.kt` | エントリポイント。HOME インテントの受け口 |
| `Graph.kt` | 手動 DI。リポジトリの生成と消えたパッケージの掃除 |
| `data/Model.kt` | データモデル(`AppRef` / `Tile` / `WorkColumn` / `DockItem` / `LayoutState`) |
| `data/LayoutRepository.kt` | レイアウトの永続化(DataStore + kotlinx.serialization) |
| `data/AppRepository.kt` | インストール済みアプリの一覧・監視 |
| `ui/HomeScreen.kt` | 画面全体の状態管理(オーバーレイ・メニュー・ピッカー) |
| `ui/workspace/WorkspaceStrip.kt` | niri 風の横スクロールワークスペース本体 |
| `ui/dock/` | ドックバーとフォルダシート |
| `ui/drawer/` | アプリドロワー |
| `util/LaunchUtils.kt` | 起動・分割起動・壁紙・デフォルトホーム等のインテント処理 |

## ビルド方法

JDK 17 が必要です。

```sh
# デバッグビルド
./gradlew assembleDebug

# リリース用 AAB(Google Play 提出用)
./gradlew bundleRelease
```

## Google Play 配信の要点

詳細な手順は [docs/PLAY_CHECKLIST.md](docs/PLAY_CHECKLIST.md) を参照してください。

1. **署名**: プロジェクトルートに `keystore.properties` を置くと、release ビルドに自動で署名されます。

   ```properties
   storeFile=release.keystore
   storePassword=********
   keyAlias=ohagi
   keyPassword=********
   ```

   `keystore.properties` が存在しない場合、release は未署名のままビルドされます(ファイルはコミットしないでください)。

2. **AAB 作成**: `./gradlew bundleRelease` で `app/build/outputs/bundle/release/` に AAB が生成されます。

3. **権限まわり**: ohagi は Play 審査で問題になりやすい `QUERY_ALL_PACKAGES` 権限を使いません。代わりにマニフェストの `<queries>` で「`MAIN` + `LAUNCHER` を持つ全アプリ」を列挙しており、ホームランチャーとして必要なアプリ一覧をこれだけで取得できます。宣言している権限は `REQUEST_DELETE_PACKAGES`(アンインストール確認ダイアログの表示、通常権限)のみです。

## フリーフォームモードについて

ohagi は起動時にフリーフォームウィンドウが使えるかを判定し、使える場合は「タイル矩形への実ウィンドウ起動」に自動で切り替わります。

実装は `ActivityOptions.setLaunchBounds`(公開 API)に加え、ホーム画面(フルスクリーンタスク)からの起動でも freeform になるよう `setLaunchWindowingMode` を [HiddenApiBypass](https://github.com/LSPosed/AndroidHiddenApiBypass) 経由で呼び出します(Taskbar など Play 配信中のウィンドウ管理系アプリで広く使われている手法です)。この呼び出しが将来の OS で拒否された場合も、自動的に通常起動へフォールバックするため機能が壊れることはありません。

- **対応端末**: `FEATURE_FREEFORM_WINDOW_MANAGEMENT` を持つ端末(タブレット・デスクトップモード対応機など)、または開発者向けオプションの「フリーフォームウィンドウの有効化」(`enable_freeform_support`)をオンにして再起動した端末。
- **非対応端末**: 従来どおりタップでフルスクリーン起動、2 タイルカラムは OS の分割画面で同時起動します。
- **ウィンドウ配置の補足**: 既に開いているウィンドウと重なる位置に新しいウィンドウを開くと、OS が重なり回避のため位置を少しずらす(カスケード)ことがあります。また `resizeableActivity=false` を宣言しているアプリ(一部のカメラアプリ等)は OS の制約で freeform にできず、フルスクリーンで開きます。

## 既知の制約

- **タイル内にアプリの生きた映像は描けません**: サードパーティのランチャーが他アプリの画面(タスクスナップショットや実映像)を取得して自分の描画階層に描くことは、Android のセキュリティモデルで禁止されています(`ActivityManager.getRunningTasks` は自アプリのタスクしか返さず、`getTaskSnapshot` はシステム署名が必須。実機同等環境で検証済み)。そのため ohagi の**非アクティブなタイルはアイコン + アプリ名のカード**で表し、リアルタイムの描画と操作は起動した**実フリーフォームウィンドウ側**で行います。
- **ウィンドウはリボンのスクロールには追従しません**: 開いた実ウィンドウは OS 管理のため、タイル位置に「置かれる」形になり、リボンをスクロールしてもウィンドウ自体は動きません(niri との本質的な違いで、上記の制約に起因します)。
- **分割起動は一部メーカー ROM で無効**: `FLAG_ACTIVITY_LAUNCH_ADJACENT` の解釈は OS 実装に依存するため、一部の端末では 2 アプリ同時起動が動作しません(その場合はトースト表示で通知します)。
- **ウィジェット非対応**: タイル 1 枚 = アプリ 1 つのモデルを保つための意図的な仕様です。
