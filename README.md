# ohagi

Linux のタイリングウィンドウマネージャー(i3 / Sway)に着想を得た Android ホームランチャーです。1 画面を固定したまま、複数のアプリを実ウィンドウ(フリーフォームウィンドウ)としてタイル状に並べて表示します。

- リポジトリ: https://github.com/hatake716/ohagi.git
- applicationId: `io.github.hatake716.ohagi`
- minSdk 26 (Android 8.0) / targetSdk 36 / versionName 0.1.0

## コンセプト

ohagi はホーム画面を「最大 3 分割できる 1 枚のタイリング領域」として扱います。アプリを開くと、その時点の分割数に応じた矩形に実際のフリーフォームウィンドウが開き、複数アプリを同時に操作できます。

以前のバージョンにあった niri 風の横スクロール(無限リボン)は廃止し、画面は 1 画面固定です。

## 主な機能

- **1 画面固定のタイリング**: 横スクロールなし。開いているアプリを最大 3 枚まで 1 画面に並べます。
  - 1 枚: 全画面
  - 2 枚: 縦画面は上下、横画面は左右に 2 分割
  - 3 枚: マスター(主ペイン)が半分、残り 2 枚がもう半分を 2 分割
- **実ウィンドウでの表示・操作**: 各ペインは OS のフリーフォームウィンドウとして開くため、その中でアプリを実際に操作できます。
- **macOS ライクなプレビュー**: ワークスペース上のペインカードは角丸で、マスターは小豆色の縁取りが強調されます。
- **4 スロット + 中央ランチャーボタンのドック**、**ドック内フォルダ管理**、**壁紙変更**。
- **ウィジェット非対応(意図的)**。

## 操作方法

| 操作 | 動作 |
|---|---|
| ペインをタップ | そのアプリのウィンドウを前面化 |
| ペインを長押し | ペインメニュー(起動 / マスターにする / アプリ情報 / このアプリを閉じる) |
| 上スワイプ または 中央ボタン | アプリ一覧(ドロワー)を開く |
| 中央ボタンを長押し | ホームメニュー(アプリ追加 / タイルを並べ直す / すべて閉じる / 壁紙変更 / デフォルトホーム設定 / このアプリについて) |
| ドロワーのアプリをタップ | タイリングに開く(4 枚目以降は最も古いペインを押し出し) |
| ドックスロットをタップ / 長押し | 起動・フォルダを開く / スロットメニュー |

## Android の制約と、その中での設計

Android のセキュリティモデルでは、**通常のアプリ(システム署名なし・Google Play 配信可能なアプリ)は、一度開いた他アプリのウィンドウを後から移動・リサイズできません**。これは `ActivityManager.resizeTask` などが `MANAGE_ACTIVITY_TASKS`(システム署名が必要な権限)で保護されているためで、`killBackgroundProcesses` も画面に見えているウィンドウには効きません(いずれも実機で検証済み)。

そのため ohagi は次の方針を取ります。

- **各アプリは「開かれる瞬間」の分割数に応じた位置に配置されます**(`ActivityOptions.setLaunchBounds`。これは配信アプリでも可能)。順にアプリを開くと、新しく開いたアプリが正しいタイル位置に並びます。
- 既に開いているウィンドウは動かせないため、**レイアウトをきれいに整え直したいときは、ホームメニューの「タイルを並べ直す」または「すべて閉じる」で開き直します**。

このため「先にアプリをすべて閉じてから、並べたい順にアプリを開く」と、最もきれいにタイリングされます。

## フリーフォームモードについて

タイリングはフリーフォームウィンドウが有効な端末で動作します。

- **対応端末**: `FEATURE_FREEFORM_WINDOW_MANAGEMENT` を持つ端末、または開発者向けオプションの「フリーフォームウィンドウの有効化」(`enable_freeform_support`)をオンにして再起動した端末。
- **非対応端末**: タップで通常どおりフルスクリーン起動します(タイリングは無効)。
- 実装は `setLaunchBounds`(公開 API)に加え、ホームからの起動でも freeform になるよう `setLaunchWindowingMode` を [HiddenApiBypass](https://github.com/LSPosed/AndroidHiddenApiBypass) 経由で呼びます(失敗時は通常起動へフォールバック)。

## アーキテクチャ概要

単一モジュール。Jetpack Compose + DataStore(JSON) + 手動 DI(`Graph`)。

| ファイル | 役割 |
|---|---|
| `data/Model.kt` | データモデル(`AppRef` / `Pane` / `DockItem` / `LayoutState`) |
| `data/Tiling.kt` | タイリング矩形の計算(1〜3 分割) |
| `data/LayoutRepository.kt` | レイアウトの永続化(DataStore + kotlinx.serialization) |
| `data/AppRepository.kt` | インストール済みアプリの一覧・監視 |
| `ui/HomeScreen.kt` | 画面全体の状態管理・タイリング起動の制御 |
| `ui/workspace/TilingWorkspace.kt` | タイリングのプレビュー / 操作面 |
| `util/TilingManager.kt` | ペイン群を実ウィンドウとして配置 |
| `util/LaunchUtils.kt` | 起動・壁紙・デフォルトホーム等のインテント処理 |
| `ui/dock/` / `ui/drawer/` | ドック・フォルダ・ドロワー |

## ビルド方法

JDK 17 が必要です。

```sh
./gradlew assembleDebug
./gradlew bundleRelease   # Google Play 提出用 AAB
```

Google Play 配信の詳細は [docs/PLAY_CHECKLIST.md](docs/PLAY_CHECKLIST.md) を参照してください。

## 既知の制約

- **開いているウィンドウはあとから動かせません**(上記「Android の制約」参照)。きれいに並べ直すには開き直しが必要です。
- **タイル内にアプリの生きた映像は描けません**: ワークスペース上のペインはアイコン + アプリ名のカードで、実際の描画・操作は開いたフリーフォームウィンドウ側で行われます。
- **ウィジェット非対応**(意図的)。
